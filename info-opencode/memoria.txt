  Proyecto: APLICACION_PUYO
===============================================

Que es Vendix?
  Aplicacion movil POS (Punto de Venta) para negocios
  en Peru. Permite registrar ventas, escanear codigos
  de barras, gestionar productos, generar reportes PDF
  y compartir boletas. Moneda: Soles (PEN).

Stack tecnologico:
  - React Native + Expo SDK 54
  - Firebase (Auth + Firestore)
  - expo-camera (escaner de barras)
  - expo-av (video splash)
  - expo-print (boletas PDF)
  - expo-sharing (compartir PDFs)
  - lucide-react-native (iconos)
  - react-native-svg (logos/Ilustraciones)

Color principal (THEME):
  - Primary/Success: #00d26a / #22B15B (verde)
  - Background: #080808 (casi negro)
  - Card: #111111
  - Texto: #FFFFFF / #8E8E93

====================================================================
  FIREBASE - ESTRUCTURA DETALLADA
====================================================================

1. Configuracion
   - Archivo: src/config/firebase.js
   - Proyecto: vendix-3cedd (Firebase)
   - La app verifica si hay apiKey antes de inicializar
   - isFirebaseConfigured booleano condicional:
       si hay apiKey → Firebase real
       si no → modo offline (solo AsyncStorage)

2. Estructura Firestore
   Cada usuario tiene datos aislados bajo:
   users/{uid}/productos/{productId}
   users/{uid}/sales/{saleId}
   users/{uid}/categories/{categoryName}
   users/{uid}/settings/branches
   users/{uid} → documento raiz del usuario (opcional)

   Reglas de seguridad (recomendadas):
     match /users/{uid}/{document=**} {
       allow read, write: if request.auth != null && request.auth.uid == uid;
     }

3. Sync Logic (App.js: loadUserDataForAccount)
   a) Al iniciar sesion onAuthStateChanged:
      - Lee AsyncStorage con claves PER-USER:
        @vendix_products_{safeUser}
        @vendix_sales_history_{safeUser}
        @vendix_categories_{safeUser}
        @vendix_custom_emojis_{safeUser}
      - Luego sincroniza desde Firestore (sobrescribe local)
   
   b) Al completar venta (handleCompleteSale):
      - Descuenta stock local y en Firestore
      - Guarda la venta en users/{uid}/sales/{saleId}
      - Actualiza productos modificados
   
   c) Al modificar productos (handleUpdateProductsList):
      - Elimina en cloud los que ya no existen en local
      - Escribe todos los actuales
   
   d) Categorias:
      - handleAddCategory: escribe en Firestore doc con { emoji }
      - handleDeleteCategory: elimina el doc en Firestore
      - loadUserDataForAccount: al cargar, si no hay categorias
        en cloud, siembra defaults (Bebidas, Snacks, Golosinas,
        Abarrotes, Lacteos)

4. Aislamiento de datos entre usuarios (data leak fix)
   - Cada usuario tiene sus propias claves AsyncStorage
   - safeUser = (email || 'guest').replace(/[^a-zA-Z0-9]/g, '_')
   - Claves:
     @vendix_products_{safeUser}
     @vendix_sales_history_{safeUser}
     @vendix_categories_{safeUser}
     @vendix_custom_emojis_{safeUser}
   - loadUserDataForAccount limpia estados (setProducts([]),
     setSalesHistory([]), setCart([])) antes de cargar los nuevos
   - Al cerrar sesion se borra loggedUser pero NO las claves
     por usuario (quedan en AsyncStorage para la proxima)
   - Al eliminar cuenta se barren todas las colecciones en
     Firestore (products, sales, categories, settings) y se
     borra el Auth user

5. Offline-first hybrid
   - Los datos siempre se guardan primero en AsyncStorage
   - firebase es secundario (sobrescribe local al loguearse)
   - Si no hay conexion o Firebase no configurado, la app
     funciona igual solo con AsyncStorage
   - Los UIDs para Firestore se obtienen asi:
     auth.currentUser.uid → si hay sesion Firebase
     email sanitizado → fallback (para invitados/demo)
     'vendix_user_main' → ultimo recurso

6. Colecciones Firestore por usuario:
   products/{id}
     { id, name, category, price, stock, minStock, barcode, image, avatar }
   sales/{id}
     { id, time, total, items, method, client, productsList,
       timestamp }
   categories/{name}
     { emoji: '🥤' }
   settings/branches
     { selectedBranch, branches: ['Mi Sucursal', ...] }
